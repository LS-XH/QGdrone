> 文档性质：AI 根据项目内 A9 手册、巡线配置 PDF、OpenMV 示例和 A9 源码整理，不是厂家协作规范，也不是新的官方协议。

> 版本说明：本文同时记录两个协议。`AC` 是已有巡线示例的 Legacy 协议；`VS V1` 是本项目视觉扫描任务的协作协议，已在 PC 端完成编解码测试，但尚未接入真实 A9 或证明适用于厂家固件。

## 目前可以直接引用的事实

- A9 用户手册 V2.4 的默认接口表写有 OpenMV UART3，同时说明串口功能可以重新配置。
- 巡线配置 PDF 要求把 OPENMV 实际接入的飞控串口配置为“二次开发 → SDI”，并把巡线主模式设置为 35。
- 当前 OpenMV 示例在设备端调用 `UART(1, 115200)`。
- 当前示例帧由 `main.py` 发送，A9 巡线版本的 `Drivers/drv_SDI.cpp` 接收。
- 当前示例发送消息类型 `2`、长度 `8`，数据区是两个由 `struct.pack('f', ...)` 生成的 4 字节浮点值。
- `Modes/M35_Auto1.cpp` 使用 `msg.cmd == 2`，并使用 `msg.params[0]` 和 `msg.params[1]`；丢线示例用第一个参数 `200`。

## AI/视觉组与嵌入式组的协作边界

视觉/AI 组可以先提交以下项目产物，但这些是协作建议，不是 A9 已经规定的字段：

- 视觉脚本、模型或算法版本。
- 测试图片/视频，以及拍摄环境和阈值说明。
- 识别到线路/目标与未识别到的测试样例。
- 如果要兼容当前巡线示例，则按已核对的两个浮点误差值输出；不要自行增加字段或改变字节顺序。

如果需要置信度、时间戳、目标框、目标类别或其他 AI 结果，必须纳入下面的 `VS V1` 设计或经两组评审后扩展版本，不能临时在 `AC` 的两个浮点数后面追加字段。

## 视觉扫描项目协议 V1：VS 二进制帧

### 1. 设计目标

AI 组只发送任务意图、扫描结果和危险信息；嵌入式组负责目标检查、坐标转换、任务状态机、安全仲裁和 A9 控制。AI 端不得直接发送解锁、起飞、原始姿态、油门或电机 PWM。

协议可以承载在 UART、USB 虚拟串口、UDP 或 TCP 上，传输层变化不改变帧格式。首版使用 `VS` 帧头，避免与巡线 `AC` 帧混淆。

完整规格见仓库设计文档：
`docs/superpowers/specs/2026-08-12-ai-embedded-protocol-v1-design.md`

### 2. 统一帧格式

```text
VS | version | flags | message_type | payload_length | sequence | timestamp_ms | payload | crc16
```

| 字段 | 类型 | 长度 | 说明 |
| --- | --- | ---: | --- |
| magic | uint8[2] | 2 | `0x56 0x53`，ASCII `VS` |
| version | uint8 | 1 | 固定为1 |
| flags | uint8 | 1 | ACK_REQUIRED=bit0，IS_RESPONSE=bit1，HIGH_PRIORITY=bit2 |
| message_type | uint16 | 2 | 小端序，见下表 |
| payload_length | uint16 | 2 | 0..128，小端序 |
| sequence | uint16 | 2 | 发送端独立递增，小端序 |
| timestamp_ms | uint32 | 4 | 发送端单调运行时间，小端序 |
| payload | uint8[N] | N | 小端整数和 IEEE754 float32 |
| crc16 | uint16 | 2 | CRC-16/CCITT-FALSE，覆盖 version 到 payload |

CRC 参数：多项式 `0x1021`，初值 `0xFFFF`，不反射，结果不异或。最大帧长144字节。

### 3. 坐标约定

任务坐标使用局部 ENU：`x` 向东、`y` 向北、`z` 向上；偏航以正北为0度，顺时针为正。任务原点由两组在任务开始前确定，执行期间不得改变。嵌入式负责转换到 A9 内部坐标系。原点未建立或 AI 定位无效时，嵌入式必须拒绝目标。

### 4. 消息类型

| ID | 消息 | 方向 | ACK |
| ---: | --- | --- | --- |
| `0x0001` | HEARTBEAT | 双向 | 否 |
| `0x0002` | ACK | 响应 | - |
| `0x0101` | SET_TARGET_LOCAL | AI→嵌入式 | 是 |
| `0x0102` | ACTION_COMMAND | AI→嵌入式 | 是 |
| `0x0103` | SCAN_STATUS | AI→嵌入式 | 是 |
| `0x0104` | HAZARD_ALERT | AI→嵌入式 | 是/高优先级 |
| `0x0201` | FLIGHT_STATUS | 嵌入式→AI | 否，建议10Hz |
| `0x0202` | MISSION_EVENT | 嵌入式→AI | 建议是 |
| `0x0203` | SAFETY_EVENT | 嵌入式→AI | 是/高优先级 |

`SET_TARGET_LOCAL` 载荷为：

```text
uint32 target_id
float32 x_m, y_m, z_m
float32 yaw_deg
float32 max_speed_m_s
float32 acceptance_radius_m
uint32 valid_for_ms
```

`ACTION_COMMAND` 的 action：1=暂停并悬停，2=继续，3=取消目标，4=结束任务并悬停，5=请求安全降落。V1 没有 AI 解锁和起飞动作。

`SCAN_STATUS` 的 status：1=完成，2=质量不足，3=发现漏扫，4=全部地图完成。漏扫位置由 AI 再次发送 `SET_TARGET_LOCAL`，不能让扫描结果消息直接触发飞行动作。

`HAZARD_ALERT` 至少包含危险中心 `x/y/z`、半径、等级、建议行为和有效期。建议行为不是强制控制，嵌入式可执行更保守动作。

### 5. ACK、重发和安全规则

- ACK_REQUIRED 消息200ms内未收到 ACK则重发，最多3次。
- 接收端按对端角色和 sequence 去重；重复消息不得重复执行。
- AI 心跳建议5Hz；1秒未收到心跳，嵌入式停止前往新目标，悬停并上报 AI失联。
- 5秒未恢复时保持人工可接管；是否自动降落必须由现场安全策略明确配置，V1默认不自动返航。
- AI 定位无效时拒绝新目标，取消当前目标并悬停。
- 目标必须经过高度、速度、围栏、最大单步距离、定位健康和飞控状态检查。
- 人工接管、A9 自身保护和物理急停高于所有 AI 指令。

### 6. FreeRTOS 接入建议

A9 原固件已经使用 FreeRTOS。V1 不重新移植 RTOS，只增加协作逻辑：

```text
UART DMA/中断
  → AI_RX 任务：收包、CRC、字段校验、去重、ACK
  → 静态消息队列
  → ScanMission 状态机：目标、悬停、补扫、暂停、结束
  → 安全仲裁
  → A9 现有 Modes / 位置控制接口
```

AI_RX 建议使用外部传感器级优先级；ScanMission 建议使用普通用户任务优先级。中断中不做路径规划，不直接操作电机、PWM或控制器；逐帧接收路径使用静态缓冲、静态队列和有界超时。

## 接入前检查清单

1. 对照原始 `博睿A9飞控接线图_V2.0.pdf` 确认插座、供电和 TX/RX/GND 线序；不要依据本说明猜线。
2. 确认实际使用的 OpenMV 型号、固件/IDE 版本和 UART 引脚；`UART(1)` 只是 OpenMV 端逻辑编号。
3. 在 GCS PRO 中确认 A9 实际接入的串口已经配置成“二次开发 → SDI”，并重启使配置生效。
4. 确认刷入的 A9 固件和源码属于对应巡线版本；仅凭文件名不能证明版本匹配。
5. 先在串口回环/抓包、无桨台架或仿真环境验证帧格式，再进行任何有动力测试。
6. 单独评审丢线、超时、断线、异常浮点值和通信中断时的控制行为；当前巡线源码中的丢线分支不能自动视为正式安全策略。
7. AI 组和嵌入式组先用 VS V1 PC 编解码测试向量互相验收，再做串口回环、无桨台架、FlightSim和受控低高度测试。
