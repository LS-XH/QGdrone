## 二、删除模型 / 删除 PLY 函数结构

> 来源《删除模型与PLY函数.md》，下面按**现状代码**（`SessionManager.cs`，2026-08-18 之后）重新核对整理。

### 2.1 两个函数

| 函数 | 签名 | 做什么 |
|------|------|--------|
| 删整个模型 | `SessionManager.DeleteModel(string modelName)` | 删 `Incoming/<modelName>/` 整个文件夹（含所有轮次、PLY、.meta）+ 大清单里整条模型记录 |
| 删单个 PLY | `SessionManager.DeletePly(string modelName, string plyAbsPath)` | 删指定 PLY 文件 + 大清单那条记录；该模型没有其它 PLY 时模型条目和文件夹一起删 |

路径常量（`SessionManager.cs`）：
- `IncomingDir` → `Assets/Data/Incoming`（`Application.dataPath + "/Data/Incoming"`，与服务器 `SAVE_DIR` 一致）
- `ModelsIndexPath` → `Assets/Data/Incoming/allModels.json`

### 2.2 大清单数据结构（`allModels.json`）

```csharp
[Serializable] public class ModelsIndex   // allModels.json 顶层
{ public string lastUpdated; public List<ModelEntry> models; }

[Serializable] public class ModelEntry
{ public string modelName; public string modelFolder; public List<PlyEntry> plies; }

[Serializable] public class PlyEntry
{ public string relativePath; public RenderMeta metadata; }
```

读写方法：
- `LoadModelsIndex()` — 读 `Incoming/allModels.json`（不存在返回空清单；损坏自动重建为空）
- `SaveModelsIndex(idx)` — 写回并刷新 `lastUpdated`

> ⚠️ **字段一致性红线**：这份大清单**同时被服务器 Node (`server.js`) 读写**，字段必须保持一致（`modelName` / `modelFolder` / `plies[].relativePath` / `metadata`）。C# 用 `JsonUtility`（严格小写匹配、不序列化私有字段），Node 用普通 JSON——两边字段名都要小写驼峰，别加新字段进去。

### 2.3 DeleteModel 逻辑

```
DeleteModel(modelName):
  1. 删本地文件夹  Incoming/<modelName>/  （Directory.Delete(dir, true) 整夹递归）
       · 失败 → LogError + return false（不改大清单，保持磁盘/清单一致）
  2. 读大清单，RemoveAll(m => m.modelName == modelName)
       · 条数变了才 SaveModelsIndex
  3. 返回 bool = 磁盘文件夹是否真的删了
```

### 2.4 DeletePly 逻辑

```
DeletePly(modelName, plyAbsPath):
  1. 删本地 PLY 文件（plyAbsPath 是绝对路径）
       · 失败 → LogError + return false
       · 从该文件所在目录一路向上，把空目录清到 Incoming 为止（不进 Incoming 本身）；
         目录里有 .meta / 其它 PLY / manifest.json 就停，不会误删
  2. 大清单移除该条记录：
       匹配规则 = 完整路径相等；或（文件名相等 **且** 所在目录相等）
       —— 即「同名只能删同一轮次夹里的」，防误删其它轮次夹的同名 PLY
       · 若删完该模型 plies 为 0 → 连模型条目 + Incoming/<modelName>/ 文件夹一起删
       · 有变化才 SaveModelsIndex
  3. 返回 bool = 磁盘 PLY 文件是否真的删了
```

> 与《删除模型与PLY函数.md》(2026-08-18) 的差异：原文档写的是「文件名相等即删」（同名不同轮次会一次删两条的隐患）。**现状代码已是「文件名 + 目录都相等」**（`SessionManager.cs` 的 `DeletePly`），隐患已修。

### 2.5 调用方式（C# 端）

```csharp
// 删整个模型（按模型名）
bool ok = SessionManager.DeleteModel("建筑A");

// 删单个 PLY（模型名 + 绝对路径，路径就是大清单里那条 relativePath / 服务器回传的 savedPath）
bool ok2 = SessionManager.DeletePly("建筑A",
    @"C:\Users\33304\Desktop\暑假培训\数字孪生平台(comperate)\QGstudio_SummerCampPlus\Assets\Data\Incoming\建筑A\20260818_122332\high_high_high_model_red.ply");
```

两个函数都是 `static`、不依赖场景：Play 模式 / Editor 菜单 / 工具脚本都能直接调；大清单路径走 `Application.dataPath`，Editor 菜单里同样可用。

### 2.6 行为与边界（现状）

1. **删到 0 条就整模型消失**：`DeletePly` 删掉该模型最后一条 PLY 后，会连模型文件夹 + 大清单条目一起删。想留空模型条目需改这段。
2. **空目录自动清理**：只清到 `Incoming` 为止；目录里有 `.meta` / 其它 PLY 就停。
3. **`DeletePly` 不删 `.ply.meta`**：只删 PLY 本体，Unity 的 `xxx.ply.meta` 会留下（目录因此非空，向上清理也停住），Unity 重扫 `Assets/Data/` 时可能报孤儿 meta 警告。仍是开放改进点。
4. **`DeleteModel` 整夹递归删最干净**：连轮次夹、`.meta` 一起删。但 Windows 上若文件被 Unity 其它模块占用，`Directory.Delete(dir, true)` 会抛异常 → 返回 `false` 且不改大清单（保持磁盘/清单一致），先停用再删。
5. **大清单是共享文件**：Node 服务器也读写同一份 `allModels.json`。C# 删完，服务器端下次 `upsertModelPly` 会重新读盘（`loadModelsJson` 每次现读），不会用旧缓存覆盖回来。唯一注意点：别在服务器正在写入的瞬间并发写（本机单用户场景基本遇不到）。
6. **返回值含义**：`bool` = 磁盘文件/文件夹是否真的删了；大清单更新失败只打 LogError 不影响返回值。调用方判断「删除成功」主要看 `bool`，但要留意日志里有没有「更新大清单失败」。

## 三、网络收到的文件怎么保存（保存结构）

### 3.1 目录结构总览

所有机器统一，收到的 PLY 都落本机 `Assets/Data/Incoming`（与服务器 `SAVE_DIR` 一致）：

```
QGstudio_SummerCampPlus/Assets/Data/Incoming/
├── allModels.json                     ← 大清单（双端共用字段，记录每个模型 + 每条 PLY）
├── 建筑A/                             ← 按模型一个文件夹
│   ├── 20260818_134226/               ← 按轮次一个文件夹（yyyyMMdd_HHmmss，与 sessionId 格式一致）
│   │   ├── high_high_high_model_red.ply
│   │   └── high_high_high_model_red.ply.meta
│   ├── 20260818_150419/
│   │   └── high_high_high_model_red.ply
│   └── 20260821_170441/               ← 新一轮
│       └── …
└── 测试2/
    └── 20260818_131851/
        └── high_high_high_model_red.ply
```

**轮次文件夹命名**：`yyyyMMdd_HHmmss`（本地时间，可排序）。服务器 `roundIdNow()` 生成，和 Unity 缺省 `sessionId` 格式一致，两边用同一个 id 对齐。

### 3.2 服务器端落盘（`server.js`）

`POST /api/v1/render/upload`（multipart）→ `parseMultipart()`：

1. busboy 解析，`defParamCharset='utf8'`（否则 Python 传的中文文件名会被 latin1 拆乱）。
2. 先写临时文件 `SAVE_DIR/.tmp_<时间戳>_<随机>.part`，等 `metadata` 字段到齐（multipart 字段顺序不定）。
3. 确定轮次：`ensureRound(metadata)` —— 有当前轮就用，没有按该 PLY 的 modelName 懒创建。
4. 落到 `SAVE_DIR/<modelName>/<roundId>/[precision_]文件名`（`sanitizeName` 过一遍，防路径穿越）。
5. `upsertModelPly(modelName, modelFolderAbs, plyAbsPath, metadata)` 更新大清单（按路径去重）。
6. 回包给 AI + 转发给 Unity：带 `savedPath`（绝对路径，同机直读）、`fileUrl`（公网下载 URL，远程图形端用）、`roundId`、`metadata`。

**精度前缀**：metadata 里有 `precision` 时文件名为 `[precision]_<原文件名>`（如 `high_high_high_model_red.ply`），精度不同不覆盖。

### 3.3 文件名 / 名字清洗（防路径穿越）

- 服务器 `sanitizeName`：过滤 `\ / : * ? " < > |`，防 `..`，超 80 字符截断，空名回退 `unknown`。
- Unity `SessionManager.SanitizeName`：与服务器一致（`Path.GetInvalidFileNameChars()` 替换、去末尾点/空格、80 字符截断）。
- 下载文件名、模型名、轮次名**都要过一遍清洗**再拼路径。

### 3.4 Unity 图形端收文件（`RenderClient.cs` HandleUpload）

收到 `upload` 消息后分两种：

```
若本机磁盘上有服务器给的绝对路径 savedPath（服务器这台机器通常就是）：
  → 直接用它渲染，不走网络（不特殊对待，照样记本机 allModels.json）

否则（远程图形端，读不到服务器磁盘）：
  1. 从 fileUrl 拆 模型/轮次/文件（TryParseFileUrl，URL 形如
     …/api/v1/files/<模型>/<轮次>/<文件>，逐段解码；顺带去掉 ?query#fragment）
  2. 拼本机库路径 Assets/Data/Incoming/<模型>/<轮次>/<文件>
  3. 本机已有同路径 → 跳过下载直接渲染
  4. 没有 → DownloadPlyAsync 流式下载（HttpClient，1GB 上限，
     超时 110s 略小于服务器 120s 回包超时；失败删掉半截文件）
```

拿到本地路径后，两条都做：
- `SessionManager.RecordPly(localPath, metadata)` — 追加到本轮会话清单 `<persistentDataPath>/RenderSessions/<sessionId>/manifest.json`（本轮开始→结束）。
- `SessionManager.UpsertLocalPly(localPath, metadata)` — 记进本机 `allModels.json`（离线浏览读它）。

然后调黑盒回调 `m_Handler.RenderPly(localPath)` 渲染，回包带 `savedPath`。

### 3.5 大清单 `allModels.json`（双端共用一份字段）

```jsonc
{
  "lastUpdated": "2026-08-21T09:04:58.596Z",
  "models": [
    {
      "modelName": "建筑A",
      "modelFolder": "C:/Users/33304/.../Assets/Data/Incoming/建筑A",  // 模型夹绝对路径（正斜杠）
      "plies": [
        {
          "relativePath": "C:/Users/33304/.../Incoming/建筑A/20260818_134226/high_high_high_model_red.ply",
          "metadata": { "modelName": "建筑A", "precision": "high", "submissionCount": 1 }
        }
      ]
    }
  ]
}
```

- 路径一律**绝对路径 + 正斜杠**（`toAbsPath` / `NormalizePath`）。
- 服务器那台机器：Node 进程写 `SAVE_DIR/allModels.json`；Unity 客户端也写同一份。
- **每台机器一份自己的索引**：所有机器（含服务器机，不特殊对待）收到 PLY 都 `UpsertLocalPly` 写本机大清单。

### 3.6 下载接口与安全（`server.js` serveFile）

`GET /api/v1/files/<模型>/<轮次>/<文件>`：
- 路径段逐段 `decodeURIComponent`（中文模型名）并校验：拒绝 `.`/`..`/含 `\` 的段。
- `path.resolve(SAVE_DIR, ...)` 后校验仍落在 `SAVE_DIR` 内，杜绝路径穿越。
- 流式返回（`Content-Disposition: attachment; filename*=UTF-8''…`）。

### 3.7 去重与防覆盖规则

| 场景 | 做法 |
|------|------|
| 服务器写大清单 | `upsertModelPly` 按 `relativePath` 规范化后去重，已有同路径就跳过（不重复追加） |
| Unity 写本机大清单 | `UpsertLocalPly` 同路径去重 + **有变化才落盘**（避免整文件重写把服务器刚写的内容覆盖） |
| 远程重复下载 | 本机库已有同路径 → 跳过下载直接渲染 |

### 3.8 会话清单（本轮记录）

`<persistentDataPath>/RenderSessions/<sessionId>/manifest.json`：
- `start` 时 `BeginSession(metadata, roundId)`（roundId 优先用服务器的），`end` 时写盘。
- 结构：`SessionManifest{ sessionId, createdAt, endedAt, status, files[] }`，files 每条 `RecordedPly{ fileName, savedPath, sizeBytes, metadata }`。
- 用途：UI 浏览「每一轮渲染」；`RecordPly` 是累积追加。

## 四、端到端时序（一条 PLY 从上传到本机库）

```
AI 组 POST /api/v1/render/upload (multipart: file + metadata)
   ↓ server.js
① 流式落盘 → Assets/Data/Incoming/<模型>/<轮次>/[精度_]文件
② upsertModelPly 写 allModels.json（服务器那份）
③ 转发 upload 给 Unity（savedPath + fileUrl + roundId + metadata）
   ↓ RenderClient.HandleUpload（主线程）
④ 同机有 savedPath → 直接用；否则按 fileUrl 下载到本机库同结构路径
⑤ RecordPly 记本轮会话清单；UpsertLocalPly 写本机 allModels.json
⑥ m_Handler.RenderPly(localPath) 渲染
⑦ 回包 upload_response（带 savedPath）
```

之后图形组 UI 想清理：
```
DeleteModel("建筑A")   → 删整夹 + 大清单整条
DeletePly("建筑A", absPath) → 删文件 + 删那条记录（空则整模型一起删）
```
